## Identity and admission

Keep `session()`, `enroll()` and `activeMember()` identity/membership semantics unchanged: authenticated exit uses them. Add a small server-only agreement helper that combines existing eligible-account validation with a valid current-version record for file use. New verified members and existing members with no current agreement see the same unchecked agreement screen before the workspace. No acceptance inferred from an invitation, login, email verification, old activity or an eligibility attestation.

POST `/api/terms/accept`: authenticated stable account ID from the session, explicit `agree: true`, exact displayed version, server timestamp. Reject unexpected fields, client-supplied identity/time, invalid membership, stale version and cross-origin requests. Use existing bounded body, CSRF, rate-limit and coordinated handler. Return a review-again error when the version changes. Server derives the active version from an immutable approved-text manifest, not request input. Repeat acceptance for the same account/version preserves the original valid timestamp. Preserve prior accepted versions; do not rewrite their text. Retention policy does not authorize deleting these records now.

## Private storage and recovery

Propose `.private/terms/<validated-account-id>/<immutable-version>.json`, reusing `privateRoot`, `privateRead`, `privateSave` and the existing `operation/coordinated` lock. Payload is only account ID, version and acceptedAt; reuse signed-record conventions with a purpose-specific signature domain and existing server secret. No email, IP, user-agent, password, session or attestation. Strict field/date/version/path/signature validation; missing record means no agreement, corruption means unavailable, not automatic replacement. Check ignore/untracked status and never include private data in client props, errors or logs.

`privateSave` uses exclusive temporary creation plus rename; the shared operation lock serializes first-write/retry decisions. It is atomic replacement, not verified power-loss durability: do not claim fsync or backup guarantees. A failed/uncertain local save must be reread and validated before retry; preserve an existing valid timestamp. Ignore incomplete temp files for admission, reconcile them under maintenance without automatic deletion. Maintenance closing/dirty markers must block agreement writes and final inventories must wait for in-flight writes.

One persistent host and private root shared by every application/operator process are mandatory. Ephemeral/serverless or multi-host activation is unsupported. Windows file mode is not proof of ACL protection: verify effective host access. Before activation, rehearse backup/restore with synthetic records: quiesce writers using the held gate, protect private snapshot and signing material separately, validate signatures/version history on restore, reconcile provider membership/current version and unfinished cases, and reopen only after checks. Do not restore old grants or bypass markers. Missing evidence must never be backfilled; fresh prospective agreement may be obtained without inventing the lost date. Retention/holds apply to controlled backup copies too; no backup-erasure promise is established.

## Expired rate-limit clarification — proposal, not execution

Indefinite retention is not approved. Proposed review trigger: before inviting testers, then during each scheduled operator maintenance review. No new numeric retention duration is invented. Preview rows whose server `expires` window has ended, using bounded pagination and an authoritative time check. Exclude unexpired rows and any specifically held/referenced preservation evidence. Under the held shared maintenance gate, reread each selected row and compare the preview digest/expiry before explicit confirmed deletion; stop on changes, uncertain writes or external-writer activity. Record only aggregate results and private necessary retry references; retries treat independently confirmed absence as completion. Exceptions require a specific reason and next review within 30 days. Existing preserved protocol limiter rows cannot be selected without separate approval. Implementation, operational review cadence and live deletion scope still need approval; no cleanup is enabled by this plan.
